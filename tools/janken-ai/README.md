# Janken AI Lab

完全ローカルで動く、プロフィール学習型じゃんけん分析ツールです。

## 対応モード

- 1対1
- AIと対戦。AIはラウンド開始時に手を決め、プレイヤーが手を選ぶと双方の手と勝敗を表示します。
- AIとすぐ対戦。対戦専用の `play.html` は手を選ぶボタン、AIの手、勝敗を表示します。結果を受けて予測を更新し、最近の手と予測モデルの成績をブラウザに保存します。
- 1対1対1（3人じゃんけん）
- あいこ判定
  - 全員同じ手
  - 3人でグー・チョキ・パーが全部出た場合
- 3人戦で同じ勝ち手が2人いる「共同勝ち」にも対応

## プロフィール

参加者ごとにプロフィールを作成し、各プロフィールへ独立して手の履歴を保存します。

保存項目:

- 名前 / アイコン / メモ
- 出した手
- 各ラウンドの勝ち / 負け / あいこ
- 対戦文脈
- 学習用イベント履歴

データは localStorage に保存され、外部送信しません。

## 独自予測エンジン

単純な出現率だけではなく、複数の特徴を重み付きで合成します。

- 全期間の手の分布
- 直近を強く見る時間減衰分布
- 前回その人が出した手からの次手遷移
- 相手側の前回手に対する反応
- 勝ち / 負け / あいこ後の変化
- 直近2手パターン
- 同じ手の連続傾向
- 学習件数と分布の偏りから確信度を算出

1対1対1では2人の相手の予測分布を組み合わせ、グー / チョキ / パー各候補について全9通りの相手手組み合わせを評価し、期待効用が最大になる手を推奨します。

AI戦略:

- バランス
- 負けにくさ重視
- 勝ち狙い

## ラウンドの流れ

1. 自分プロフィールを選ぶ
2. 相手プロフィールを1人または2人選ぶ
3. AIが推奨手を表示
4. 実際にじゃんけんする
5. 全員が出した手を選択
6. 勝敗 / あいこを自動判定
7. 各プロフィールへ個別に学習
8. 次の推奨手を再計算

## その他

- セッション勝敗集計
- ラウンド履歴
- 直前ラウンド取り消し
- プロフィール分析
- 手の分布グラフ
- 次手予測
- バックアップJSON書き出し / 読み込み
- ライト / ダークテーマ
- 完全ローカル、CDN/APIなし

## 強化版学習モデル

現在の予測は以下をアンサンブルします。

- 全体傾向
- 直近を重視した時間減衰傾向
- 現在の試合だけの傾向
- 1対1 / 3人戦ごとの傾向
- 特定プロフィールとの直接対戦傾向
- 前回手からの次手遷移
- 「同じ手 / 相手に勝つ手 / その他」への変化傾向
- 自分が前回出した手への反応
- 勝ち / 負け / あいこ後の変化
- 2手 / 3手 / 4手のN-gramパターン
- 同じ手の連続傾向

各モデルはサンプル数と分布の偏りに応じて自動的に重みを変えます。少数データだけで強く決めつけないよう平滑化しています。

### 3人戦の相関補正

同じ2人の相手と3人じゃんけんを繰り返した場合、相手Aと相手Bを完全に独立とは扱いません。
過去に2人が同時に出した手の組み合わせを学習し、データ量に応じて最大72%まで経験的な同時分布を反映します。

### AI自己評価

強化版以降のラウンドでは、実際に手が出る前の予測分布を保存します。

- TOP予測命中率
- 実際に出た手へ割り当てていた平均確率
- 現在のモデル確信度
- 特定相手との専用学習件数

をプロフィール分析画面で確認できます。

## 自動適応モード

「自動適応」では、AIの確信度に応じて内部戦略を切り替えます。

- 低確信度: 負けにくさを優先
- 中程度: バランス
- 高確信度: 勝ちを狙う

データがほぼ無い場合には、同点候補を固定し続けないように初期提案も分散させます。

## クイック学習

プロフィール一覧の「過去の手でクイック学習」から、過去に出した手をまとめて追加できます。

対応例:

- グー チョキ パー グー
- ✊ ✌️ 🖐️ ✊
- R S P R

勝敗情報が無い履歴でも、出し手頻度・遷移・N-gram学習に利用されます。

## 対戦復元

進行中の試合は localStorage に保存します。
ページを再読み込みしても、参加者・モード・戦略・ラウンド履歴を復元して続行できます。

## モデルの差し替え

Web配布の更新対象はこのフォルダーの `model.js` です。同じスキーマのモデルに差し替えて再読み込みすると、1対1の予測に適用されます。オフラインでは最後に取得したモデルを使います。基本モデルは公開データで学習した疎な INT8 モデルと、0.5B 教師から蒸留した INT4 モデルの合成です。対戦中は直近最大64手を順に再生して、現在の相手に適応します。3人戦はプロフィール予測と同時出し相関を使います。

Python 3.12 の PyTorch 環境で `python scripts/train-janken.py <data.json> --checkpoint <teacher.pt> --output <candidate.js>` を実行すると、単体で動く INT4 候補が得られます。チェックポイントは約2 GBのため作業用ドライブに置いてください。Python側で試合を周回ごとにシャッフルし、各入力にはそのラウンド以前の双方の手だけを含めます。教師の活性化するパラメータは1局面あたり約1,790万、全体で約5億です。

学習データは [公開研究ログ](https://github.com/erik-brockbank/hm_rps_public/tree/77edd3a54741433e550a68bd5c9248086b05e676/data/human_data) から抽出した双方の手です。参加者ごとに分離した学習48,417手・検証10,020手・試験10,928手を使用しました。合成比率は検証セットで選びました。試験ログでは、試合内で適応する疎なモデルの64手制限なしの命中率67.08%に対し、合成は67.50%。対数損失は0.7415から0.7317でした。

### 適応型決定木の再学習

現行モデルは疎な INT8 と蒸留 INT4 の予測に、直近の反復・勝敗後の反応・双方の手の遷移を使う決定木を合成しています。各遷移予測には、同じ対戦の過去に出した予測の成績も特徴として入力します。決定木の葉は16ビット整数に量子化しています。古いランタイムでも同じファイルから従来の予測を実行できます。

```sh
node scripts/janken-features.cjs data.json training-output 2
python scripts/train-janken-adaptive.py training-output training-output/candidate.js --feature-version 2
node scripts/select-janken-adaptive.cjs data.json tools/janken-ai/model.js training-output/model.js training-output/candidate.js
```

学習スクリプトは CatBoost、LightGBM、NumPy を使用します。特徴量はブラウザと同じ JavaScript で生成し、その手を出す前に観測できる最大64手だけを使います。検証セットで合成比率と確率の温度を選び、最後に試験セットで量子化済みのモデルを測ります。以前の64手制限なしの試験値とは比較条件が異なります。

同じ64手制限で試験10,928手を比較すると、次手命中率は66.60%から69.65%、対数損失は0.7395から0.6804でした。これは試験ログでの予測成績です。

学習・モデル選択と別に評価した[人間同士の対戦データ](https://github.com/erik-brockbank/rps-games-analysis/tree/9f07e145abf1c56e13fd2cc22cba7e950aed6d24/data)では、双方を予測対象とした35,938件で45.26%から49.69%でした。

### 1B 教師モデルの追加学習

過去最大64手の特徴から共通ネットワークが最初の予測を出します。同じ特徴を使って、学習データから作った分岐で64個の専門モデルのうち1個を選びます。各専門モデルは共通ネットワークの予測に加える補正を学びます。ブラウザ用の候補は教師の確率分布を学習した4ビット量子化モデルです。

新しいコーパスは [Brockbank の v3 実験ログ](https://github.com/erik-brockbank/rps/blob/b8b30a8ffbff2c860daff03d649bb1b1c7563211/analysis/rps_v3_data.csv) から作ります。既存の実験ログ2件と試合ID・参加者IDを照合し、参加者IDごとに学習・検証・試験へ分けます。別研究の [WXZ2014](https://search.r-project.org/CRAN/refmans/stratEst/html/WXZ2014.html) 全21,600手は外部評価に使います。ログから出力するのは双方の手の列のみです。

```sh
python scripts/prepare-janken-new-data.py rps-v3.csv WXZ2014.rda new-corpus.json --exclude rps-v2.csv rps-v1.csv
node scripts/janken-features.cjs new-corpus.json new-features 2
python scripts/train-janken-routed.py new-features new-teacher --epochs 4
node scripts/compare-janken-routed.cjs new-corpus.json original-corpus.json new-teacher/student.json candidate.js
```

Python環境には PyTorch、NumPy、pyreadr が必要です。学習時はチェックポイント用に約4 GBの空き容量が必要です。比較では、公開モデルと候補の合成比率を検証セットで決め、試験セットと外部評価データは最終比較に使います。

今回の教師は1,002,011,553パラメータで、1回の予測に15,703,650パラメータを使います。従来のログを再学習には使わず、新規41,810手で教師を学習しました。公開版は蒸留モデルと従来モデルの確率を50%ずつ合成しています。

| 試験ログ | 従来の命中率 | 公開版の命中率 |
| --- | ---: | ---: |
| 新規 v3 の未見参加者 10,082手 | 54.51% | 55.90% |
| 従来の試験ログ 10,928手 | 69.65% | 69.49% |
| 人間同士の外部ログ 21,600手 | 52.12% | 51.69% |

### 対戦専用画面の追加学習

[OpenNeuro ds006761](https://github.com/OpenNeuroDatasets/ds006761/tree/51d35252b4b9a0ebe6483ad7eaf8b1d8accdd3a1) のイベント表から双方の手を取り出しました。同じ二人の対戦は同じ分割に置き、学習19,808件、検証4,712件、試験4,750件に分けています。次の手を予測する前に見える情報だけで、異なる時間幅の手の偏りと条件付き遷移を評価しました。

```sh
python scripts/prepare-janken-openneuro.py events openneuro.json
node scripts/janken-features.cjs openneuro.json features 3
python scripts/train-janken-adaptive.py features tree.js --feature-version 3 --trials 4
node scripts/compare-janken-play.cjs openneuro.json v3-corpus.json original-corpus.json tree.js candidate.js
```

`events` には31組分の `*_events.tsv` を `sub-01.tsv` のように参加者番号で保存します。検証データで合成、周期予測、対戦中の確率補正を比較します。採用した確率補正は、実際に選んだ手と各手に付けた予測確率との差を蓄積し、次の予測に反映します。履歴と補正値は対戦専用画面からブラウザに保存します。

試験4セットでは、補正後の次手命中率は新規OpenNeuroが43.56%（従来43.77%）、v3が55.96%（従来55.90%）、従来の人工対戦相手とのログが69.49%（同率）、WXZ2014が51.78%（従来51.69%）でした。

### 過去の手の並びを使った再学習

従来コーパス、v3、OpenNeuroの学習分割を合わせた137,385手で決定木を学習しました。直近64手から、自分の手、手の変化、双方の手、勝敗の並びを照合し、似た並びの直後に出た手を特徴に加えています。近い時点の一致を重く扱います。

再現するには、3コーパスを分割ごとに連結し、学習分割から重複する対戦列と、検証・試験・外部評価にも含まれる同一の対戦列を取り除いて `pooled.json` を作ります。

```sh
node --max-old-space-size=5000 scripts/janken-features.cjs pooled.json pooled-features 4
python scripts/train-janken-adaptive.py pooled-features tree.js --feature-version 4 --trials 4
node scripts/select-janken-refinement.cjs tree.js candidate.js original-corpus.json v3-corpus.json openneuro.json
```

合成比率と周期予測の採否は、3コーパスの検証分割の平均命中率と対数損失で決めます。対戦専用画面と同じく、各試験では次の手を入力に含めず、予測の後で履歴と補正を更新します。

再学習した決定木に60%、従来モデルに40%の重みを付けています。4種類の試験ログ47,360手を合計すると、命中数は26,489手から26,680手に増えました。

| 試験ログ | 従来の命中率 | 更新後の命中率 |
| --- | ---: | ---: |
| OpenNeuro 4,750手 | 43.56% | 45.16% |
| v3 10,082手 | 55.96% | 56.19% |
| 従来の試験ログ 10,928手 | 69.49% | 69.66% |
| WXZ2014 21,600手 | 51.78% | 52.12% |

### 対戦途中で変わる傾向の学習

[Guennouni と Speekenbrink の公開対戦データ](https://github.com/mspeekenbrink/sdam-r/blob/93245a342bf0d6c5c4cf26d9cab124b67920e51c/data/rps.rda)から、新たに52人の2,600手を取り込みました。各参加者の50手をまとめたまま、1,500手を学習、550手を検証、550手を試験に使います。学習には既存の学習分割も合わせ、計138,885手を使います。

選択頻度、勝敗後の変化、相手の手に対する反応を、異なる長さの履歴から見積もります。各方式は過去の手を順番に予測し、実際の手に事前に付けていた確率から信頼度を更新します。これらの値を決定木と4ビット量子化ニューラルネットの特徴にも使います。

```sh
python scripts/prepare-janken-transfer.py rps.rda transfer.json
node --max-old-space-size=5000 scripts/janken-features.cjs pooled-with-transfer.json pooled-v5 5
python scripts/train-janken-adaptive.py pooled-v5 tree.js --feature-version 5 --trials 2
python scripts/train-janken-routed.py pooled-v5 neural --feature-version 5 --student-only --epochs 16 --threads 4
node scripts/select-janken-opponent.cjs tree.js neural/student.json candidate.js original-corpus.json v3-corpus.json openneuro.json transfer.json external-holdout.json
```

`pooled-with-transfer.json` は、前節の `pooled.json` の各分割に、対応する `transfer.json` の分割を加えたものです。検証で改良方式と合成比率を選び、試験では固定します。

採用した4ビットモデルの合成比率は60%を基準とし、従来モデルより確信度が高い予測では比率を上げます。

| 試験ログ | 従来の命中率 | 更新後の命中率 |
| --- | ---: | ---: |
| 新規の人間対AIログ 550手 | 60.73% | 61.82% |
| OpenNeuro 4,750手 | 45.16% | 45.52% |
| v3 10,082手 | 56.19% | 56.68% |
| 従来の試験ログ 10,928手 | 69.66% | 69.78% |
| WXZ2014 21,600手 | 52.12% | 52.03% |
| 人間同士の外部ログ 8,588手 | 51.75% | 51.73% |
| 全試験 56,498手 | 55.68% | 55.80% |

### Roshambo.meの実対戦ログによる追加学習

Elias Bouacida と Renaud Foucart による「Rituals of Reasons」の公開資料に含まれる、Lasse Hassing提供のRoshambo.me対戦ログを使います。[公開元](https://entrepot.recherche.data.gouv.fr/dataset.xhtml?persistentId=doi:10.57745/NZTMN9)のファイル398373には455,180行があります。SHA-256は `1e6166bfb8cdea62d2ea16966381dab0d76f4e35ed80fa767126dc7657641e45` です。データのライセンスは [CC BY-NC-SA 4.0](https://entrepot.recherche.data.gouv.fr/api/access/datafile/398329) です。

1がグー、2がパー、3がチョキです。同じラウンド番号であいこが続く場合も、ファイル内の順番を維持します。無効な手では履歴を切り、4手以上有効な対戦だけを使います。同じ手列と双方を入れ替えた手列を一組として重複を除き、既存データと同じ列も取り除きます。両者の視点は同じ分割へ置きます。

追加分は学習413,008手、検証89,102手、試験87,800手です。既存分と合わせて551,893手で学習します。参加者IDは含まれないため、分割は対戦列単位であり、同じ参加者かどうかは照合できません。

```sh
python scripts/prepare-janken-roshambo.py roshambo.tab roshambo.json --exclude pooled-with-transfer.json v3-corpus.json external.json
node scripts/janken-features.cjs pooled-with-roshambo.json fresh-features 5
python scripts/train-janken-routed.py fresh-features fresh-network --student-only --feature-version 5 --threads 6 --epochs 12 --student-width 160 --student-hidden 64 --seed 90311 --training-source-rounds 75767,41810,19808,1500,413008 --validation-source-rounds 10020,8698,4712,550,89102 --source-weights 2,2,2,1,2
```

`pooled-with-roshambo.json` は前節の学習データの各分割に、対応する追加データを加えます。特徴ファイルは512手ずつ書き出します。変換中に全サンプルの特徴をメモリへ保持する必要がありません。

モデル選択には次のコマンドを使います。`JANKEN_CHALLENGER` に新しいネットワークの `student.json` を指定し、`JANKEN_VALIDATION_ONLY=1` を設定すると試験を行わずに候補を比較できます。設定を外して再実行すると、固定した候補を試験して `comparison/model.js` に出力します。

```sh
node scripts/tune-janken-confidence.cjs comparison original-corpus.json v3-corpus.json openneuro.json transfer.json external-holdout.json roshambo.json
```

検証で選んだ設定では、最初の8手で旧ネットワークと追加学習ネットワークの出力を平均し、それ以降は旧ネットワークの出力を使います。平均は確率を出す直前のスコアで行います。従来の木・蒸留モデルとの合成と対戦中の補正は継続します。

| 試験ログ | 更新前 | 更新後 |
| --- | ---: | ---: |
| Roshambo.me 87,800手 | 37.04% | 37.32% |
| 従来の6種類 56,498手 | 55.80% | 55.81% |
| 合計144,298手 | 44.39% | 44.56% |

合計では252手多く当たりました。従来の人工対戦相手とのログと転移学習データでは、それぞれ4手減っています。90%は未達です。モデル重みの配布条件と出典は [MODEL-LICENSE.md](MODEL-LICENSE.md) に記載しています。

### 裏読み・ランダム混合への対戦学習

対戦専用モデルを追加しました。既存の学習分割138,885手に、12種類の相手と4種類の自分の出し方で新たに生成した92,160手を加え、計231,045手で学習しています。自分と相手は手を確定してから互いの手を受け取ります。現在の相手の手を予測入力に含めません。

オンライン側は、自分・相手の直前の手、手の組、勝敗、連続した手、周期を両者の立場からモデル化します。短期・長期の記憶と3段階の読み替えを合わせた168種類の予測に、均等予測、従来モデル、追加学習モデルを加えます。それぞれに実際の次の手へ事前に付けていた確率で重みを更新します。1回の外れで履歴を消す方式は使っていません。

追加ネットワークは675入力、48・16ユニットの中間層を持つ33,249パラメーターの共有スコアモデルです。4ビット量子化後の検証41,260手で次手命中率65.61%でした。この検証には人間の対戦ログと生成ログが含まれます。対戦用重み・設定・最終試験結果は `model.js` の `battleModel`、`battlePolicy`、`battleEvaluation` に格納しています。

手の選択では、勝ちと負けの予測差から確率分布を作り、その分布を `crypto.getRandomValues` でサンプリングします。予測成績や実際の収支が悪い間は、分布を均等に近づけます。単純な相手を読めている間は攻める割合を増やします。予測と実際に出す手は区別し、入力された現在の手を見て出し直す処理はありません。

最小対戦画面とラボ内の「AIと対戦」に同じ仕組みを導入しています。再読み込みではオンラインの重みと集計を復元し、ラウンドの取り消しでは取り消した観測の学習も戻します。

設計の参考として、[Daniel Lawrence LuによるRPSアルゴリズムの説明](https://daniel.lawrence.lu/blog/2011-01-01-rock-paper-scissors-algorithms/)と、[Exponential Weightsによるオンライン学習の研究](https://arxiv.org/abs/1802.07543)を参照しました。実装と検証用相手は本プロジェクトのJSです。ユーザーが実際に負けた相手のコードは未提供のため、同一の相手の再現試験ではありません。

対戦設定は13種類の検証用相手、乱数種6100〜6102、各240手で選びました。最終試験は乱数種19000〜19007に固定し、追加の未学習タイプを含む16種類、各500手、各版64,000手で比較しています。旧版はコミット `d12908e` の最小対戦方針で、人間ログ用モデルの出力は旧版と一致することを確認しています。

### ランダムな手を挟む周期とあいこへの対応

2〜24手周期、8種類の履歴幅での頻度読みとその裏、両者の直前の手に条件付けた予測を追加しました。周期の同じ位置に現れた複数の手を集計し、単発の予測ミスを許容します。直近の予測成績が既存モデルを上回るときに追加予測の比率を上げます。

追加予測の確率と過去の成績を入力に加え、対戦用ネットワークを231,045手で再学習しました。同じ41,260手の検証では量子化後の命中率が65.61%から66.91%、対数損失が0.7479から0.7355に改善しました。手の選択では勝ちの価値を1、負けを−1、あいこを−0.2として比較し、予測が不確かなときは均等に近い選択を続けます。

対戦設定は乱数種8100〜8103で選択しました。別の乱数種28000〜28007で16種類の相手と各500手ずつ対戦し、`aba06d5` の公開対戦方針と比較しました。全指標にあいこを含む64,000手を使っています。

| 指標 | 更新前 | 更新後 |
| --- | ---: | ---: |
| 勝率 | 63.32% | 66.15% |
| あいこ率 | 19.58% | 17.45% |
| 負け率 | 17.10% | 16.40% |
| 次の手の命中率 | 67.31% | 68.98% |
| 周期にランダムを混ぜる相手への勝率 | 60.75% | 81.98% |
| 出す頻度を読む相手への勝率 | 57.35% | 72.43% |

実ログの再生では次手命中率がOpenNeuroの4,750手で41.60%から41.35%、別の人間対AIの550手で55.27%から56.36%でした。記録済みの手にはAIが選択した手の影響がないため、実ログでは勝率を測定していません。均等に独立に出す相手は次の手を当てる期待値が3分の1です。

### 直前の展開が似た局面からの予測

直近96手の各局面を現在と最大6手まで照合します。相手の手、自分の手、両者の手、手を同じだけずらした並び、直前の勝敗という5つの見方で、似た局面の直後に相手が出した手を集計します。照合が長く新しいほど、その手の重みを増やします。周期や頻度からの予測も並行して続け、これまでの予測結果が良かった方式へ、その場で重みを移します。

これらの確率と成績を入力に加え、231,045手で対戦用ネットワークを再学習しました。同じ41,260手の検証で、採用した小型ネットワーク単体の命中率は旧版66.91%に対して66.81%、対数損失は0.7355から0.7290でした。幅を広げた候補の単体命中率は67.02%でしたが、採用した候補の方が設定選びに使った対戦で勝ち数と負け数の差が大きくなりました。

設定は乱数種9600〜9603で選び、別の乱数種39000〜39007で18種類の相手と各500手、各版72,000手を対戦しました。同じ条件の `4539005` と比較しています。

| 指標 | 更新前 | 更新後 |
| --- | ---: | ---: |
| 次の手の命中率 | 65.23% | 66.56% |
| 勝率 | 62.04% | 63.52% |
| あいこ率 | 19.67% | 19.23% |
| 負け率 | 18.29% | 17.25% |
| こちらの直近4手に反応する相手への勝率 | 37.50% | 46.93% |
| 手の相対関係から反応する相手への勝率 | 36.00% | 45.48% |

手の遷移を読む相手など、一部への勝率は低下しました。実ログの再生では計5,300手で2,274手から2,325手へ増え、OpenNeuroは41.35%から42.48%、別の人間対AIは56.36%から55.82%でした。2種類とも対数損失は改善しています。実ログでは、記録された次の手の予測を評価しました。総合90%は未達です。

### 序盤特化と裏読み、神経回路 3D

対戦モデルを標準・広域・序盤の3系統に拡張しました。入力は各候補手684特徴、隠れ層はそれぞれ48・16、80・32、72・24で、合計142,203パラメーターです。3系統の重みは4ビット量子化しています。序盤モデルは231,045手の訓練時に序盤の誤差を重く扱い、対戦時も序盤で高い混合比を持ちます。

相手がこちらの手をコピーする、先読みしてその手に勝つ、その読み返しを予想するなど、8通りを並行で評価します。予測は直近の実績で重み付けし、手の選択ではあいこの確率にもペナルティーを付けています。相手の手を受け取る前にAIの手を確定します。

設定選びに使った乱数とは別の44000〜44013で、18種類の相手と各96手、各版24,192手を対戦しました。最初の12手は各版3,024手です。比較対象は `ec142b8` です。

| 指標 | 最初の12手・旧版 → 新版 | 96手・旧版 → 新版 |
| --- | ---: | ---: |
| 勝率 | 42.89% → 47.92% | 59.88% → 61.45% |
| あいこ率 | 28.87% → 25.93% | 20.99% → 19.88% |
| 負け率 | 28.24% → 26.16% | 19.14% → 18.67% |
| 次の手の命中率 | 52.58% → 53.47% | 63.46% → 63.47% |

こちらの直前の手に勝つ相手への勝率は3.42ポイント、負けると戦法を変える相手への勝率は6.40ポイント上がりました。両者の手の相対関係で反応する相手への勝率は2.23ポイント下がりました。人間の記録5,300手の再生では、次の手の命中率は43.87%から43.66%に下がりました。
