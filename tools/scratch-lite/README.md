# Scratch Lite Launcher

Scratch/TurboWarp プロジェクトを、編集画面を出さずに再生する軽量ランチャーです。

## 2.0 の読み込み経路

- .sb3のZIP索引・project.json解析・素材展開・CRC32検証をWeb Workerへ移動。
- 小さい素材はfflate、大きい素材はDecompressionStreamで展開。圧縮ファイルが64MB以下ならワーカー内で1回だけ保持し、それより大きいファイルは必要な範囲を読む。
- ローカルFile/BlobをそのままワーカーとIndexedDBへ渡し、メイン画面でファイル全体のArrayBufferコピーを作らない。展開済みの素材はtransferableで受け取る。
- 素材供給は端末に応じて2〜12並列。同じassetId・形式への重複要求を共有。無制限に素材を一斉展開しない。
- ネストしたsetTimeoutの待ち時間を避け、MessageChannelで画面操作へ処理を譲る。
- 総合の工程進捗は0〜100%の目安。ダウンロード量に加え、VMのASSET_PROGRESSで画像・音声・フォントの展開完了件数を表示。100%は作品構築と最初の描画準備が終わってから表示する。
- 解析など処理量が決まらない段階では待機表示にし、架空の残り時間や一定速度の疑似進捗は表示しない。
- 画像の縮小・再圧縮・素材の削除は行わない。エラー時には素材キューとワーカーを終了し、不完全な作品を起動しない。
- 再読み込みでは既存のVM・WebGL描画領域を再利用。別作品へ移ると前のプロジェクトと保持Blobを解放する。
- Scaffolding 0.4.0を同梱し、ランタイム読み込みのCDN依存を減らす。単一HTMLの書き出しにもワーカーと展開ライブラリーを含める。

従来のArrayBuffer形式で保存された履歴も読み込めます。.sb/.sb2やワーカーが使えない環境は標準の互換経路へ戻します。ZIP64・暗号化・特殊圧縮なども互換経路の対象です。高速経路では個別の展開素材は256MB、project.jsonは64MBまで検証します。画質を維持した大量のテクスチャ・音声のデコードには依然として端末のメモリと時間が必要です。

URLで取得するproject.jsonの外部素材や拡張機能には、別途接続が必要な場合があります。ローカル.sb3は作品の全素材を同梱している場合にオフラインで再生できます。

### 検証

`npm test` にZIP読み取り、圧縮方式、CRC破損、サイズ上限、キュー上限と終了処理の検証を含みます。

ローカルHTTPサーバーを起動し、Playwrightを使用できる環境で次を実行します。必要なら `PLAYWRIGHT_MODULE` と `SCRATCH_BASE_URL` を指定してください。

- `npm run test:scratch` — 実作品の読み込み、進捗、素材欠落、再読み込み、履歴、描画領域の増殖防止。
- `npm run test:scratch-flows` — Pythonで合成素材を作成し、SB3/JSON/SB2、緑の旗、保存済み旧形式、ワーカー非対応、失敗後の復旧、URL、通常Webと単一HTMLのオフライン動作を確認。
- `npm run measure:scratch` — 同じ作品で変更前のコミット2eac454と比較。入力作品は `SCRATCH_PROJECT_PATH` で指定でき、変更しません。計測結果は `output/scratch-test/comparison.json` に保存します。

### 実作品での確認（2026-11-06）

最新版の「本編_軽量版.sb3」（23,889,809 bytes、582ターゲット、103,318ブロック、28,786コスチューム参照、176音声）を使用。17,586種類の素材を読み込み、欠落0件、進捗100%、再読み込み・履歴からの起動でも描画Canvasは1個のままでした。

同じPC・Chromium・自動開始OFFでの初回ローカル読み込みの単回参考値です。

| 指標 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 読み込み時間 | 26.97秒 | 25.24秒 |
| UIタイマー間隔の最大値（50ms間隔で観測） | 1,895ms | 1,012ms |
| 50ms以上のメインスレッド処理の合計 | 1,923ms | 1,350ms |

総読み込み時間の改善は端末・作品に依存し、画像の大量デコード自体は残ります。この結果は主に画面の応答性改善を示すもので、すべての作品の高速化率を保証しません。

## 主な機能

- `.sb3` / `.sb2` / `.sb` ファイル読み込み
- Scratch / TurboWarp URL またはプロジェクトID読み込み
- 直接URL読み込み（CORSで許可されているURLのみ）
- 読み込み前に `project.json` を先読みして作品の重さを推定
- CPU論理コア数、メモリ目安、作品規模から自動設定
- TurboWarpコンパイラを常時利用
- 30 FPS互換を基本に、描画品質・補間・高品質ペン・クローン上限を自動調整
- ターボモード、Warpタイマー、クローン上限、Fencing、Misc limits を手動調整可能
- ブロック/コード/スプライト一覧を表示しない再生専用UI
- 一度開いた作品をIndexedDBへ保存し「最近開いたプロジェクト」から1タップ再読込
- URL/プロジェクトIDも取得済みデータを優先して再利用
- 保存済み解析結果も再利用するため2回目は再解析不要
- Service Workerでランタイムをキャッシュ
- 「オフラインHTMLを書き出す」でScaffolding with-musicを埋め込んだ単一HTMLを生成

## オート最適化

AUTOでは、カスタムFPSで作品速度を壊さないことを優先して通常30 FPSを維持します。
負荷が高いときは描画品質を段階的に下げ、補間や高品質ペンをOFFにします。
ペンや3D系を検出した作品では、補間を原則OFFにします。

## ローカル動作

### 一番簡単
Web版を一度開き、設定の **オフラインHTMLを書き出す** を使います。
生成された `scratch-lite-offline.html` は単一ファイルで、ローカルの `.sb3/.sb2/.sb` をネット無しで再生できます。

### このフォルダを直接配布する場合
`vendor/scaffolding-min.js` を置けば、ローカルHTTPサーバーでも外部CDN無しで起動できます。
通常の公開版では公式jsDelivrからTurboWarp Scaffolding 0.4.0を取得し、ブラウザキャッシュへ保存します。

## 注意

- ScratchのカスタムFPSは作品のロジック速度を変える場合があるため、AUTOでは30 FPSを基本にします。
- 高品質ペンは負荷が高いため、AUTOでは高性能端末かつ軽量なペン作品に限定します。
- URL直接読み込みは配信元のCORS設定に依存します。
- Scratchの未共有プロジェクトはIDだけでは取得できません。ファイル保存して読み込んでください。
- 本ツールはScratch Foundationとは無関係です。
